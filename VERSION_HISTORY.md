# Історія версій — СтеляПро

> Документ узагальнює історію розробки за доступними GitHub Pull Request, змінами гілок і зафіксованими результатами тестування. Це журнал етапів роботи, а не твердження, що кожен пункт уже пройшов повний регресійний тест на пристрої.

## Поточна версія

- **Базова версія застосунку:** `0.6.1`
- **Тестові збірки GitHub Actions:** після інтеграції відповідної конфігурації можуть мати версію `0.6.1-<номер запуску>`.
- **Android package:** `com.andreyceilings.app`
- **Основна гілка:** `main`
- **Репозиторій:** [aleks-nl5/andrey-ceilings-android](https://github.com/aleks-nl5/andrey-ceilings-android)

## Історія змін

### Підготовка застосунку та базові функції

- Створено Android-застосунок для роботи з проєктами стель.
- Підготовлено нативний Android-інтерфейс українською мовою та основну навігацію.
- Додано демонстраційні позиції прайсу.
- Реалізовано базові сценарії роботи з клієнтами й об’єктами, замірами та кошторисами.
- Додано розрахунки площі, роботу з кошторисами (зокрема дублювання й видалення) та експорт кошторису в PDF.
- Як архітектурну вимогу визначено використання Go для основної логіки з нативним Android UI. Поточна історія змін нижче описує Android-репозиторій; сама вимога не означає, що всі компоненти вже перенесені на Go.

### Безпека бази даних та діагностика

#### 2026-10-23 — діагностика SQLCipher

- **PR #1 — Add live SQLCipher diagnostic checks:** додано діагностичні перевірки версії SQLCipher та читання `sqlite_master` через активне з’єднання Room/SQLCipher.
- **PR #2 — Fix SQLCipher diagnostic compilation error:** виправлено помилку компіляції у діагностичному коді.
- Діагностика призначена для перевірки зашифрованого з’єднання й не повинна змінювати ключ або дані користувача.

### Експорт, перевірка та відновлення резервних копій

#### 2026-10-24 — перевірка зашифрованого експорту

- **PR #3 — Add encrypted database test export:** додано експорт копії бази SQLCipher через системний вибір файлу Android; перед копіюванням завершується робота з WAL. Ключ БД не експортується.
- **PR #4 та #5 — Verify encrypted database snapshot before export:** додано перевірки цілісності експортованого знімка, доступності схеми з ключем і неможливості прочитати зашифровану схему звичайним SQLite без ключа.
- **PR #6 та #7 — Verify exported SQLCipher database snapshot correctly:** уточнено перевірку саме створеного файла за допомогою SQLCipher/Room; статус експорту зроблено помітнішим і стійким до закриття системного вікна збереження.

#### 2026-10-24 — імпорт і стабільність роботи з файлами

- **PR #8 — Add encrypted database backup verification and restore:** додано окремі дії перевірки та імпорту резервної копії. Перед заміною поточної БД копія перевіряється; імпорт потребує підтвердження, а під час помилки передбачено спробу відновити попередню базу.
- **PR #9 — Fix backup import temporary file handling:** виправлено сценарій, у якому повторний вибір тієї самої копії міг призводити до помилки `ENOENT`. Для кожної перевірки використовується окремий тимчасовий файл, а невдалі тимчасові копії очищуються.
- Під час подальшого тестування користувач підтвердив, що сценарії експорту й імпорту резервних копій працюють надійно.

### Автоматичне резервування

#### 2026-10-24 — тригери та графік резервування

- **PR #10 — Add configurable automatic backup triggers:** додано налаштування автоматичного резервування за графіком (щодня, щотижня або щомісяця), під час переходу застосунку у фон та після змін у базі даних.
- Збережено політику утримання до п’яти автоматичних копій у відповідному механізмі резервування.
- **PR #11 — Confirm before disabling the last scheduled backup mode:** додано підтвердження перед вимкненням останнього активного режиму резервування. Скасування діалогу має залишати поточні налаштування без змін.

### Переносні копії та інтеграція в основну гілку

#### 2026-10-24 — переносні резервні копії

- Додано переносний формат резервної копії `.stpb`, захищений окремим паролем.
- Додано перевірку пароля та цілісності перед відновленням переносної копії.
- Передбачено перенесення зашифрованої бази між установленнями з повторним захистом ключа бази на пристрої призначення.
- У налаштуваннях резервування передбачено вибір папки, збереження параметрів автоматичного резервування та керування тригерами.
- Для цих сценаріїв додано залежності AndroidX DocumentFile та WorkManager.

#### 2026-10-24 — PR #12 інтегровано в `main`

- **PR #12 — Merge automatic and portable backup fixes into main:** об’єднано гілку `feat/automatic-and-portable-backups` з `main`.
- Включено виправлення перемикачів автоматичного резервування та конфігурацію версій тестових збірок через номер запуску GitHub Actions.
- Версія в коді налаштована так, щоб формувати `versionCode = 600000 + GITHUB_RUN_NUMBER` і `versionName = 0.6.1-<номер запуску>`, коли змінна запуску доступна.

## Основні рішення та обмеження

- **База даних:** має бути зашифрована SQLCipher; перевірка цілісності та читання схеми з ключем — частина діагностики й перевірки резервних копій.
- **Фотографії, креслення та PDF:** за рішенням проєкту ці файли окремо не шифруються.
- **Паролі й ключі:** ключ бази не має потрапляти у звичайний експорт БД. Для переносної копії використовується окремий пароль.
- **Безпека відновлення:** поточна БД має замінюватися лише після перевірки копії та явного підтвердження користувача.
- **Перевірки:** наявність реалізації або злитого PR сама по собі не підтверджує проходження всіх тестів. Перед релізом слід перевірити успішну Android-збірку, установлення APK, запуск, збереження даних після перезапуску, розрахунки кошторису, експорт PDF, зашифровану БД та повні сценарії резервного копіювання/відновлення.
