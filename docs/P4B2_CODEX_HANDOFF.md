## 2. Single-measurement quote composition UX

Open B2 via an explicit accessible action in the normal measurement Details view, with label "Попередній кошторис". A single full-screen CMP editor:
1. **Mandatory base**: financially included APPROVED/CONFIRMED `CANVAS` and `PRIMARY_PROFILE` (exactly one of each). They may not be deselected. Missing, duplicated, role-less, unpriced, invalid main role or corrupt source blocks both full and partial. Valid catalog unit price **0.00** is valid and not a missing price.
2. **Confirmed optional**: include priced valid optional work initially; let the user explicitly exclude it for **this quote only**. Excluded CONFIRMED optionals go into a precise omitted list with `USER_EXCLUDED` reason; unresolved CONFIRMED optionals list their real error reasons (no invented quantity/zero price). Selecting/deselecting does not edit `MeasurementElement`, `ElementApproval` or catalog.
3. **Discussing/potential**: separate list, unselected initially. User may explicitly select a valid priced `DISCUSSING` work into this particular quote **with visible "обговорюється" labeling**. This does not modify approval in measurement. Unselected discussing works never count toward quote sum or mark it PARTIAL; selected discussing works count exactly once, with their original source/status displayed. Unresolved discussing works remain advisory and cannot be silently billed.
4. UI shows label, unit, captured/declared source quantity, optional effective billable quantity, catalog unit price, row sum and whether it is confirmed or selected-while-discussing. Use source labels and human friendly errors, not raw UUID/signature. Do not introduce a separate price picker or manual unit-price editor.

### Quantity override, experimental and removable

- CANVAS (captured area, m²) and PRIMARY_PROFILE (captured perimeter, м.п.): default billable = measured, optional user explicit confirmed billable override for **this quote only**, show **both** source and effective; one line and one charge, no second line, no geometry change. "Повернути із заміру" removes override.
- Optional ADDITIONAL_WORK override: *only for clearly eligible, validated, individually declared exact quantities* (`ElementQuantity.Exact` with a compatible MANUAL/ENTERED_LENGTH quantity mode and unit, if the existing contract allows); reject `Unknown`, `Range`, derived geometry quantities, inappropriate placed/geometry linked conditions and anything that could silently contradict placement or double charge. For `шт.`/`компл.`, only integer pieces; for allowed length/area up to three fractional digits and current bounds. If a particular class cannot be supported safely, leave its quantity read-only with an explanation instead of broadening every override. Ensure source/effective are distinct and changing overrides doesn't mutate source. Keep implementation well isolated to allow complete feature rollback before P4C without schema change.
- Invalid or intermediate numeric input must never reuse the previous ready/acknowledged total. Explicit confirm/commit input state before applying an override; errors inline and no coercion/rounding.

## 3. Single discount on entire quote (owner decision)

- One and only one **overall percentage** applied ONCE to the **sum of selected included valid rows** (including explicitly selected discussing rows). Do not discount potential-only, omitted/unresolved, deselected or unavailable rows. No per-line discount, catalog price change or manual unit-price override.
- Default = 0%. Allow 0..100 inclusive. For a deterministic first version, store a validated exact percentage as **integer basis points** (0..10000 = 0.00%..100.00%; support up to 2 decimal percent digits via the shared editor; `0.` is partial). If differing UI precision is required, document and test it without floating point.
- KMP calculation: subtotal exact `Long` cents, discount amount = `round_half_up(subtotal * discountBasisPoints / 10000)` **once on the aggregate**, then final = subtotal - discount; use overflow-safe split/checked arithmetic (intermediate multiplication must not spuriously overflow when result is representable). Percent 100 -> final 0, legitimately. Show subtotal, percent, discount amount, final; never reprice rows after applying discount.
- Include percent and actual discount inputs/tokens in the **composition fingerprint** and in any partial acknowledgement identity. A discount change invalidates prior ack; a source/catalog or row/override change also invalidates it. The final preview signature must remain scope-bound and cannot be reused across source or measurement sessions.

## 4. Full/partial and in-place acknowledgement

KMP model automatically decides FULL vs PARTIAL; **no mode toggle**. In a PARTIAL quote, display visible **exact omitted CONFIRMED optional rows with reasons** and the badge "Частковий". Use **one checkbox embedded in the screen**, not an extra confirmation dialog. Only explicit checked action acknowledges the **exact** selected/omitted rows+reasons, source/catalog/geometry signatures, overrides, overall discount, and current composition. Any change resets it; returning after source/catalog change or database unavailability also resets it. No hidden missing line or synthetic 0. Mandatory/main/fatal errors block both FULL and PARTIAL. Partial acknowledgment is a local preview state, **not** save permission or a persisted status. P4C must later recheck atomically before writing.

## 5. Transient measurement-session lifecycle and stale safety

- The memory-only quote draft belongs to `verified measurementUuid + distinct visit/session identity`, not a global cache and not a single Composable's lifetime. Details -> quote -> Details -> quote retains selection/overrides/discount. Same-measurement Details <-> Edit keeps the session, **but always revalidates persisted pricing**, and uncommitted dirty drawing must hide ready totals. Session ends when leaving that measurement to list, project/other tab/measurement, DB restore/session replacement, or app process destruction. No timer based expiry, no disk/SQL persistence. Background/resume by itself must not drop a living session; rotate/recompose should preserve the session in a live process, but a process death/restoration starts a new quote with original source and 0 discount.
- Navigation transitions (including Back, predictive Back, tab changes and window host) should own opening/disposing the session. If leaving with nondefault changes, optionally provide a simple human-friendly warning before abandoning; no implicit Save. Session cleanup must not depend solely on Composable `onDispose` or `rememberSaveable`, which can outlive the intended scope after restoration.
- Guard async reads/events by session identity to discard late responses from previous measurements/visits; don't surface a previous total under a new measurement. On detected source/catalog/roles/geometry/approval/version changes: trigger coherent refresh/revalidation; show loading or stale error and **do not display an old total as ready**, with selection/missing keys/override compatibility re-evaluated deliberately (never remap keys by title). DB unavailable -> no stale successful fallback, no acknowledgment.

## 6. Scrolling UI with moving summary (owner-approved animation)

- While list is scrolling, a **small sticky total immediately under the top navigation bar** shows **final amount after overall discount** and optionally "Частковий". The full breakdown (subtotal, discount percent, discount amount, final) lives in the final summary at the **bottom of the scroll content**.
- When that final summary naturally reaches the viewport bottom, it should **emerge from below the visible content** as the user scrolls; the sticky top total smoothly fades/moves out. On reverse scroll, inverse handoff. Model it as one authoritative shared pricing state, not duplicate calculators. Do not display simultaneously competing top/bottom readouts or jump scroll position when the top bar collapses.
- Animate from **actual measured visibility/position of the final summary relative to scroll viewport**, not percent of list length, item index or gesture direction. Make it stable for short content, long content, resized desktop window, rotation, inset changes, keyboard open, dynamic row edits, fling and overscroll. Consider steady height for sticky container with opacity/translation animation to prevent layout jump. When final summary is already fully visible without scrolling, keep one clear accessible amount.
- Loading/fatal/stale/unavailable: show "Сума недоступна / Перевірте замір" instead of a previously valid amount in BOTH places; confirmation unavailable. Accessibility: single actionable semantic announcement of total (hide decorative duplicate from semantics when transparent), reduced-motion fallback, keyboard focus order, small screens, light/dark themes.
