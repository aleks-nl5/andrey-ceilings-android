# SQLDelight на Android — актуальний стан PR #22 (2026-10-29)

> Це актуальна специфікація стану гілки `architecture/cmp-kmp-migration-v2`. Старі плани, де Android описано як Room-програму, більше не застосовуються.

## Реалізовано

- Android використовує **SQLDelight 2.4.1** та зашифровану SQLite через SQLCipher; Room runtime і KSP Room compiler видалено.
- `:shared` містить спільну SQL-схему, SQLDelight-запити, репозиторії й `Flow` для **клієнтів, об'єктів, замірів, прайсу та кошторисів**.
- Windows/JVM та iOS Simulator перевіряють цю ж схему з платформними SQLCipher-драйверами. Це поки **не** готовий Windows/iOS застосунок.
- На фізичному Android підтверджено встановлення, запуск, створення/видалення клієнтів, об'єктів, замірів та кошторисів, повний CRUD прайсу, автоматичне резервування, експорт, перевірку й імпорт БД. Редагування інших чотирьох сутностей **ще не реалізоване в UI**, не позначати як перевірене.
- `CeilingsDatabase` не надає фальшивий Room `openHelper` / `invalidationTracker`: діагностика читає SQLDelight напряму, WAL має типізований результат, а сповіщення про зміни — `SqlDelightChangeTracker`.
- `.stpb` містить зашифрований знімок і захищений паролем конверт. Перевірка працює без заміни чинної БД. Старий імпортер Room-v2 залишається лише як допоміжна сумісність для вже написаних тестів та старих копій; **нова робоча база не імпортує стару тестову БД при запуску**.

## Нова тестова схема: підготовка до майбутньої синхронізації

На всіх п'яти таблицях зберігаються:
- `id`: локальний `INTEGER` для поточної UI-навігації та внутрішніх зв'язків;
- `uuid`: унікальний стабільний ідентифікатор запису (UUID v4), який не змінюється під час звичайного редагування;
- `updatedAt`: мілісекунди Unix epoch, записуються при створенні та оновленні;
- `deletedAt`: `NULL` для активного запису або timestamp м'якого видалення.

Звичайні запити й лічильники не показують записи з `deletedAt`; репозиторії мають окремі методи `tombstones()`. Видалення об'єкта в одній транзакції позначає видаленими його кошториси. Заміри свідомо лишаються незалежними (сумісність із попередніми зв'язками). Унікальність `(category, code)` прайсу стосується лише активних позицій, щоб після видалення можна було створити нову позицію з тим самим кодом.

**Це НЕ синхронізація:** немає облікових записів, сервера, передачі змін, конфліктів, мережевого API чи синхронізації між пристроями. UUID не є секретами або ключами доступу. Локальні `id` потрібно буде зіставляти за UUID під час майбутнього імпорту між пристроями.

### Правило щодо старої тестової БД

Власник дозволив **не мігрувати існуючі тестові дані**. Нова зашифрована БД використовує окреме ім'я `andrey_ceilings_sqldelight_v2.db`. Файли `andrey_ceilings_sqldelight.db` та `andrey_ceilings_secure.db` не стираються й не перезаписуються; після встановлення цього APK застосунок починає з нової тестової БД. Не трактувати це як безпечну production-міграцію реальних даних.
