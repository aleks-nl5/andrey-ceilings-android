# Контекстна довідка та повідомлення в інтерфейсі — глобальний UX-стандарт StelaPro

> **Погоджено власником 23.11.2026.** Постійний стандарт для **всього застосунку**: Android, iOS, Windows, спільний KMP/CMP UI. Поширюється на нові та змінювані екрани: заміри, креслення, прайс, клієнти, об'єкти, кошториси, налаштування тощо.
>
> **Статус:** нормативна UX-специфікація, **не твердження про завершену реалізацію**. Саме додавання документа не вмикає міграцію всіх старих екранів, не змінює дані/БД і не скасовує приймання APK. У поточному P5B насамперед застосувати до POINT/LINE/AREA, відступів, кількостей і Save.

## Мета

Максимально чисті форми без постійних абзаців пояснень, але з доступною інформацією **за запитом** і очевидним сигналом про проблеми. Розмежовувати **довідку про функцію**, **поточний стан** і **помилку**; не приховувати критичну інформацію заради мінімалізму.

## Поведінка

| Ситуація | У звичайному вигляді | При натисканні / активації |
| --- | --- | --- |
| Неочевидне поле або дія | Нейтральна компактна постійна **`?`** біля назви/дії | Невелике плаваюче вікно з конкретним поясненням, одиницями виміру й коротким прикладом, якщо потрібно |
| Некритична інформація | Короткий стан/значення, без постійного описового тексту | За потреби контекстна info-іконка з деталями |
| Попередження, незавершені дані, needsReview | Компактний **warning** індикатор біля відповідного поля/рядка/показника, не лише колір | Що потрібно перевірити, чим це впливає і як виправити |
| Помилка введення/валідації | Помітне виділення поля + **error `!`** або однозначна іконка поруч; без довгого червоного абзацу під полем | Точна причина, допустимі значення, дія для виправлення |
| Збереження/дія заблокована | Помітний, доступний **error/warning** індикатор **поруч з дією**, а не лише неактивна кнопка | Конкретна причина блокування і шлях до виправлення; не покладатися на клік по disabled-кнопці |
| Тимчасове завантаження/результат дії | Короткий доречний прогрес або підтвердження | Не маскувати нескінченне завантаження під довідку; для помилки результату показати доступний індикатор з діагностикою |

- **Жодного постійного нижнього пояснювального поля/футера** на кшталт «Натисніть ? для пояснення»; цей рядок використовувався лише в демонстрації, **не є частиною UI**.
- **`?` — постійна довідка** для *неочевидних* понять/операцій, не біля кожної зрозумілої кнопки. Вона не замінює видиму назву поля, одиницю виміру чи необхідну дію.
- Іконка попередження/помилки з'являється **за фактичної проблеми**. Не показувати помилку для незаповнених ще не редагованих полів до доречного моменту валідації (втрата фокусу, спроба застосувати/Save тощо); не засмічувати форму під час вводу.
- Помилку **не можна визначати тільки кольором**. Видимість і доступність мають працювати у світлій/темній темах та при збільшеному шрифті. Коли валідація відновилася, індикатор і блокування оновлюються одразу, без повторного відкриття екрана.
- Контекстна допомога не повинна захоплювати фокус вводу без потреби чи змінювати draft; **жодних прихованих застосувань значень/Save** при відкритті або закритті пояснення.

## Плаваюче пояснення: спільний CMP interaction contract

- Легке прив'язане до іконки **popover/tooltip, відкривається явним tap/click або клавіатурною активацією**. Hover на Windows може бути додатковою зручністю, **не єдиним способом** читання.
- Відображати заголовок (коли корисний), 1–3 короткі змістовні речення, числовий приклад за потреби. Уникати технічних кодів, сирих винятків, абсолютних X/Y креслення та довгих інструкцій.
- Позиція динамічно підлаштовується до меж viewport, safe areas, IME/клавіатури, нижньої панелі, масштабування шрифту й вузького екрана; текст не обрізається і не перекриває без виходу критичне керування. За недостатнього простору допустимий адаптивний легкий overlay із тією ж поведінкою, **не громіздкий звичайний AlertDialog для довідки**.
- Закривається повторним натисканням, дотиком поза ним, Back/Escape або доступною кнопкою закриття, коли це необхідно; не скидає чернетку/введення. Одночасно не більше одного такого пояснення; після закриття фокус повертається до контексту.
- Контраст, **touch target орієнтовно ≥48 dp** або платформний доступний мінімум, TalkBack/VoiceOver/Windows screen readers: зрозумілі локалізовані `contentDescription` та стан/рівень критичності, keyboard focus, Enter/Space/Escape. Для важливих змін стану — відповідні live semantics, не тільки прихований текст в іконці.

## Безпечні винятки

- **Критичні/невідкладні наслідки** (конфлікт версій, втрата даних, невдале збереження, неможливість відновити роботу) мусять залишатися **очевидними без натискання на `!`**: видимий короткий статус, доречна blocking error surface або діалог із потрібною дією. Іконка відкриває **деталі**, а не ховає єдине повідомлення про ризик.
- Підтвердження незворотних/небезпечних дій (видалення, відкидання незбережених змін, явне перенесення payable quantity) залишається **окремим доступним confirm dialog**, не перетворюється на tooltip.
- Для складної багатоетапної допомоги допускається окрема довідкова сторінка за вибором користувача; **не** створювати постійний текст під формою або навчальний футер.
- Показник, який не можна чесно розрахувати, має залишатися «—»/недоступним із warning status, **не** підмінятися збереженим або вигаданим числом.

## Архітектура, локалізація, перевірка

- Реалізовувати як **повторно використовувані shared CMP компоненти** (умовно `ContextHelpIcon`, `ValidationIssueIcon`, `ContextExplanationPopover`) з єдиними правилами розміщення, severity, overlay та семантики; не дублювати платформний UI або state-management у кожній формі.
- Опис довідки, заголовки, причини, приклади та a11y — **Compose Multiplatform Resources** з українською source/fallback, згідно з [LOCALIZATION_STRATEGY.md](LOCALIZATION_STRATEGY.md). **Особисті назви позицій/груп прайсу не перекладати**. Не переносити UI-текст у domain/SQL/PDF та не змінювати версії або immutable snapshots заради відображення.
- Розрізняти `severity`, `anchor`, `message resource/args`, `remediation`, `blocking`; модель/валідація визначає помилку, presentation layer визначає іконку та popover. Точні розміри/кольори не фіксуються тут як pixel-perfect дизайн.
- Приймання: перевірити **help + warning + blocking error + recovery** для форми й загального Save; Android normal/fullscreen + IME/Back, Windows mouse/keyboard/Escape, iOS touch/VoiceOver за доступності, збільшений шрифт, обидві теми; локалізовані a11y labels; тест, що **немає постійного пояснювального футера**.
- Переоснащувати існуючі екрани **поступово в погоджених задачах**, не проводити масову міграцію без окремого scope. Для P5B див. [P5B UX SPEC §4.3](../P5B_UX_SPEC.md).
