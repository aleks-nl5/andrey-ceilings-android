# P4A — validated KMP live-pricing preview (read-only)

**Статус: технічний контракт для реалізації Codex після окремого погодження/запуску.** Parent [#44](https://github.com/aleks-nl5/andrey-ceilings-android/issues/44), [#71](https://github.com/aleks-nl5/andrey-ceilings-android/issues/71), [#76](https://github.com/aleks-nl5/andrey-ceilings-android/issues/76), [#78](https://github.com/aleks-nl5/andrey-ceilings-android/issues/78). Базою є merged [PR #103](https://github.com/aleks-nl5/andrey-ceilings-android/pull/103) (P3C5; main merge `3d6bfff832f41a4dc59db09b2bae9d17f26cb114`; SQLDelight/SQLCipher **v14**). Далі — P4B CMP UX і P4C нове immutable estimate save, кожен окремо. Після них UX [#95](https://github.com/aleks-nl5/andrey-ceilings-android/issues/95).

## 1. Мета і межі
Побудувати **одне детерміноване ядро read-only розрахунку в shared/commonMain**: валідований замір/контур + measurement-owned POINT/LINE/AREA + `MeasurementElement` + явно обрані базові позиції прайсу → перевірений, пояснюваний **живий preview майбутнього кошторису** (рядки, ціни, кількості, тотали, попередження, блокери, версії). Не створювати паралельний калькулятор, дубль прайсу чи Android-only правила. Результат — API для майбутнього CMP P4B та P4C, **не** новий кошторис або PDF вже в P4A.

**Поза scope P4A:** нові Compose екрани/UX, редагування/переміщення Canvas, збереження draft кошторису, створення серії/ревізії, PDF, масове перепрайсування, зміна існуючих цін, геометричний solver #70, SQLCipher migrations без доведеної потреби, повноцінний iOS host #42. Не вмикати автоматичне pricing історичних кошторисів.

## 2. Чинна архітектура, яку обов'язково повторно перевірити
- `measurement/MeasurementElement.kt`: `ElementSource.Wish` або `CatalogSelection(priceItemUuid,code,quantityMode,placementKind,availability)` **без sale price**; `ElementQuantity.Unknown/Exact(milli)/Range/CeilingArea/CeilingPerimeter`, approval, placement і placedQuantity незалежні.
- `measurement/MeasurementEditStore.kt` / `db/CeilingEditRepository.kt`: єдиний coherent measurement document та journal/CAS для contour+POINT+LINE+AREA; child-only зміни можуть не збільшувати `room_measurements.updatedAt`.
- `measurement/MeasurementGeometryCodec.kt`, `estimate/FrozenPolygonGeometry.kt`, `calculation/KmpCeilingCalculator.kt`: verified captured geometry, зафіксована точність, KMP geometry. Не створювати фіктивну точність для historical shapes.
- `prices/PriceCatalogModel.kt`, `prices/PriceCatalogStore.kt`, `db/BusinessRepositories.kt`: активні `price_items` + активні `price_groups`, UUID, immutable semantic code, unit, quantityMode, placementKind, sale price, updatedAt, soft delete.
- `estimate/ImmutableEstimateRepository.kt`, `estimate/EstimateRecalculationRepository.kt`: історичні серії/ревізії, snapshots і reprice previews **не** є P4A writer. Не змінювати public history semantics або `kmp-v1` golden vectors.
- Перед реалізацією прочитати `AGENTS.md`, roadmap, issue #44, поточні схеми `BusinessSchema.sq` та migration v14; орієнтуватися на *фактичний* main, не на застарілі архівні зрізи.

## 3. Домени і API
Проєктовані назви (можна адаптувати до існуючого стилю, але семантика незмінна):
- `LiveEstimateSource`: project/measurement UUID, captured geometry + precision, coherent persistent document (active elements, point/line/area overlays, version set/receipt), **явно заданий** список базових line selections за catalog UUID (наприклад, полотно м² та профіль м.п.); жодного авто-визначення за назвою або порядком каталогу.
- `ActiveCatalogSnapshot`: лише активні catalog items з активними групами, UUID, code, unit, quantityMode, placementKind, salePrice, updatedAt, group UUID/version.
- `LiveEstimateLine`: stable source key (`base:<role>` або `element:<measurementElementUuid>`), measurementUuid, optional elementUuid, catalogItemUuid, stableCode, title, normalized unit, quantityMilli, unitPriceCents, totalCents, quantityOrigin (`CAPTURED_AREA`, `CAPTURED_PERIMETER`, `DECLARED_EXACT`, `EXPLICIT_BASE`), review flags. Жодного dependence від Canvas pixel координат.
- `LiveEstimatePreview`: sorted deterministic lines + blockers/warnings, totalCents, `canConfirm` як майбутня capability (у P4A **ніколи** не викликати save), source signature / catalog token для майбутнього транзакційного recheck. Typed failure states (parent unavailable, invalid geometry, price not found, catalog metadata drift, incompatible unit, ambiguous quantity, stale/coherent read failure, overflow, DB unavailable); жодного тихого $0 fallback.
- Pure `buildPreview(source, catalogSnapshot)` окремо від SQLDelight read adapter. Read adapter обов'язково бере **один узгоджений транзакційний зріз** measurement, children, catalog+groups та версійних токенів; не комбінувати незалежні hot Flows, що дають суміш станів. Після mutation повертати новий snapshot; стара чернетка або preview не стають «чинними» автоматично.

## 4. Правила кількості і ціни
1. **Тільки явно обраний каталог**: ідентичність за `priceItemUuid`, звірка code, unit, quantityMode, placementKind та активності item+group. Selection-time snapshot не містить ціни; для *нового* preview прочитати live sale price. Якщо позицію видалено/перенесено несумісно/змінено метадані — typed blocker, без rebinding за title або code, без позичених дефолтів.
2. **Базові рядки:** полотно й профіль мають бути вибрані явно і тільки один раз для відповідної базової ролі; `CEILING_AREA` → валідована площа у м², `CEILING_PERIMETER` → валідований периметр у м.п. Не приписувати матеріал з legacy `materialType` чи без явного зв'язку. Якщо базова позиція не вибрана, показати `NEEDS_SELECTION`, а не підставляти `KmpCeilingCalculator.defaultPriceList()`.
3. **Measurement elements:** каталогові `APPROVED` з `Exact` і unit-compatible ціною формують максимум **один рядок на element UUID**, незалежно від числа фізичних placements. Для quantityMode `CEILING_AREA`/`CEILING_PERIMETER` — тільки відповідна derived quantity з captured geometry; `MANUAL`/`ENTERED_LENGTH` — лише явно підтверджена `Exact` з коректною одиницею (м.п. для entered length). `Wish`, `DISCUSSING`, `Unknown` та `Range` залишаються видимими як `NEEDS_INPUT/UNPRICED`, не перетворюються на нуль або середину діапазону; включення/виключення з кошторису пізніше має бути явним. Не допустити непомітного «готового» кошторису із пропущеними необхідними рядками.
4. **Placed vs declared:** `placedQuantityMilli`, фактичні point count/line length/area і `APPROXIMATE/EXACT` — контрольні величини та status/review, **не приховане джерело нової фінансової кількості**. Для LINE окремий measured length не переписує заявлену `Exact`; для AREA геометрична площа й declared quantity незалежні. Sticky unresolved/review є видимими; preview не вважається confirmable без явного усунення/погодження блокувальних станів майбутнім P4B.
5. **Annotations:** `AREA role=OBSTACLE/VOID_MARKER` без explicit compatible catalog element — лише позначки: **не віднімати** площу, не генерувати ціну, не змінювати периметр, не інтерпретувати отвір як 2D boolean cutout. Коди `light.*` тощо не створюють кошторисний рядок за самою назвою.
6. **Одиниці:** не змішувати `м²`, `м.п.`, `шт.`, `компл.`, `послуга` та custom units. Цілі `шт.`/комплекти — тільки за явно валідованими правилами; unsupported custom unit без явно визначеної семантики → blocker. Нульова **наявна** ціна продажу дозволена як справжнє 0, але missing/deleted/invalid не позначати нульовою.
7. **Математика:** quantity у canonical Long milli, sale price — перевірена кількість **копійок Long** (ціна у БД зараз REAL; convert only with strict 2-decimal cents check), підсумок рядка = half-away-from-zero round(cents × milli / 1000) **один раз за рядок**, total = точна сума цілих копійок. Guard на overflow, NaN, negative, overprecision; без `Double` для множення грошей і без неявного кількаразового округлення. Повага до зафіксованої geometry precision; не міняти її під час перерахунку.
8. **Детермінізм/ідемпотентність:** same validated source+catalog snapshot → byte-for-byte equivalent preview, stable line ordering/keys, без duplicate charge при повторному reload/Flow або overlapping POINT+LINE+AREA. Content token включає всі визначальні версії та зміни у child records, не лише parent `updatedAt`.

## 5. Persistence / concurrency
P4A read-only: **жодних INSERT/UPDATE у production tables, жодної schema v15**, якщо відсутня окремо доведена технічна потреба. Не торкатися SQLCipher key/WAL, restore/backup, receipts/tombstones, numbering, historical estimates/revisions/PDF. Для майбутнього P4C зберегти `sourceSignature`/catalog signature і контракт повторної перевірки **в одній DB write transaction** без TOCTOU; P4A не удає, що один лише token захищає майбутнє збереження. `ImmutableEstimateDraft`/`ImmutableEstimateLine` — тільки майбутнє адаптування на P4C без writer у цьому PR.

## 6. Критерії готовності і тести
- [ ] Pure commonTest: rectangle 4×3 (12 м², 14 м.п.), custom polygon, captured precision; базові area/perimeter та approved точкові/лінійні/AREA категорії; manual exact і derived; 1 element → 1 line, order-independence; no double count.
- [ ] Wish/discussing/Unknown/Range/nonmatched units/deleted item or group/metadata drift/changed price/explicit zero price → typed deterministic problems, жодного synthetic default. Unplaced/partial and APPROXIMATE/EXACT/review combinations visible, no false-ready.
- [ ] Unit / money edge tests: `шт.`, `м.п.`, `м²`, unsupported units, decimal 0.005 rounding, exact cents/half-away, 0.01 price, max/min guard, overflow and precision; totalCents == sum(lineCents).
- [ ] Real SQLDelight + physical SQLCipher Android/Windows/iOS where CI supports: atomic coherent read under child-only mutation, catalog edit/deletion during preview, stale signature, closed/wrong-key DB fail-closed, no writes; preserve schema fingerprints v14 + migration/backup/restore invariants.
- [ ] Same-final-SHA CI: Android APK+unit/instrumentation, Windows/JVM UI/physical DB and iOS framework/simulator tests; if no running iOS host, explicitly say so. APK smoke owner only where actual Android behavior changed.
- [ ] Docs: refresh roadmap/AGENTS, explain P4A boundaries, P4B/P4C follow-up, all known pending limitations. No checkbox marked until actual tests succeeded. One feature branch, Draft PR; no automatic merge.
