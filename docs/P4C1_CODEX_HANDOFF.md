## 0. Strict scope and behavioral contract

Implement first **explicit Save** of **one** independently named individual quote from **one saved measurement** into one immutable `estimate_series` + one **v1** frozen revision with an assigned permanent number, plus:
1. Read-only frozen v1 detail and a single consistent list accessible from the measurement, its project and the global "Кошториси" tab (three routes to the **same** series, not three copies).
2. Persisted series-level workflow status: **DRAFT «Чернетка»** initially, **SENT «Надіслано»**, **APPROVED «Погоджено»**, **REJECTED «Відхилено»**. Any direct transition allowed, independently of measurement approval/project status. Status-only CAS metadata update **does not** make a new revision, reprice or change a frozen field.
3. Settings-driven customer-visible number with **required suffix**, while the **full series UUID stays private**. Future issuer/company profile [#114](https://github.com/aleks-nl5/andrey-ceilings-android/issues/114) is separate.

**DO NOT implement:** editing financial fields of saved v1, creating v2/v3 via UI, repricing an existing series, any PDF/reprint/printing/consolidated object documents, autosave, inline legacy calculator changes, arbitrary price editor, separate numbering subsystem, cloud sync, full issuer profile, geometry solver #70, complete UX overhaul #95. Existing previous-revision APIs should keep working but not be newly surfaced for P4C1.

## 2. Owner-approved first-Save UX

In **Попередній кошторис** include a text field **«Назва кошторису»** with default exactly the current saved measurement name. Edit inline, no mandatory dialog. Trim/validate blank/invalid/oversized names; no writes while typing. The title belongs to a new saved series/v1, not the measurement, and does not identify the document (duplicates allowed). Changing the title does not change the pricing fingerprint, but the exact submitted name is captured by Save.

Place **«Зберегти кошторис»** after the full financial summary at bottom of scroll content (respect sticky→summary handoff and system/keyboard insets). Enable only for validated FULL, or PARTIAL **with current explicit acknowledged omissions**; never for pending inputs, missing mandatory canvas/primary profile, fatal/unresolved selected work, stale source/catalog, DB unavailable or an in-flight save. Explain blocked action inline. One tap creates a **single** deterministic operation, shows a non-blocking progress state, and on **commit success only** navigates to the newly saved **read-only v1 card** with printable number, title, status DRAFT, frozen snapshot and totals. On failure keep preview and typed error, no fake success, no number reservation.

Leaving/backing/cancelling the unsaved screen must remain free of estimate/number/status writes; this is a **new** explicit action, not a change to existing B2 lifecycle.

## 3. Atomic writer and idempotency

- Take a **single writer-gated SQLDelight transaction** (respect Android SQLCipher physical gate, restore close/admission, Windows readers, iOS) and **within this very transaction** load and verify exact project/measurement ownership+active state, validated geometry/wall/receipt/placement+catalog snapshot, source/roles/approval, every explicitly included/excluded/omitted key+reason, eligible billable overrides, selected DISCUSSING intent, quantity/price/unit versions, total/fractional discount, source+catalog+scope+ack identity. No pre-read authorization outside the writer transaction. If reusing `LivePricingReader`, avoid deadlock when closing/awaiting reader leases and transaction nesting.
- Compare exact expected pre-Save signatures/token and metadata from the captured explicit Save request, not a new implicit reprice. Status=FULL/PARTIAL must be re-derived. PARTIAL requires acknowledged **exact omitted CONFIRMED set and reasons bound to the same complete fingerprint**; a checked checkbox in UI or a stale fingerprint alone does not grant writes. Unselected DISCUSSING work is not billed; explicitly selected but now unavailable blocks. Missing/duplicated/non-confirmed mandatory canvas/profile blocks even PARTIAL. Unit price **zero is valid**; missing catalog entry is NOT zero.
- Recompute in the same pure KMP `Long` cents/milli pricing and `QuoteDiscount` aggregate **once** (basis points 0..10000; half-up on selected subtotal), overflow checks and strict equalities. Validate every frozen row and each line UUID only once. `Double` is not authoritative, no 0.01 fuzzy reconciliation.
- **Idempotency key:** one freshly allocated operation UUID for a single explicit Save intent. Persist it with a UNIQUE index (or an equivalent exact receipt row) **inside** the atomic create; repeated same request returns the original series UUID/result even when the callback is retried/late, without consuming a second number. Different separately requested creation generates a new op token and a new independent series. DB commit failure must roll back **all** reserved sequence, draft rows, v1, status and receipts. Never issue one Save twice due to recomposition, double tap or app host callbacks. No guarantee of recovering an *unknown* lost request ID after complete process destruction: saved list must show committed documents to avoid confusing users.
- A series owns one number once. No mutation of measurement/ElementApproval, catalog, older price snapshots or previous estimate revisions. No automatic new revision after changing status.

Freeze full source for later drawing/PDF; do not merely store geometry reference by measurement UUID.
- fixed order+IDs of included rows with sourceKey/elementUuid/catalogUuid/stableCode/title/unit/role/approval bucket/sourceQuantityMilli/effectiveBillableQuantityMilli/origin/override note/unitPriceCents/rowTotalCents and currency/rounding/version fields. Include valid price 0 as explicit price, not absent. Captured source quantity must not be overwritten by billable override.
- frozen precise subtotal cents, one discount basis-point value, discount cents, final total cents, FULL/PARTIAL marker; complete omitted CONFIRMED optional items and exact reason codes, with acknowledgement proof. No duplicate financial lines for canvas/profile, excluded or unselected potential. Contract for integrity and backward-compatible versioning; parsing corrupt payload must fail explicitly, never fall back to repricing.
- immutable **v1** and series title snapshot; status is **mutable metadata outside** v1. Read-only card and all three lists read **frozen data** even if source measurement/catalog is modified/deleted later. Physical deletion of source must not strand frozen snapshots; maintain provenance IDs without forcing on-delete cascade to immutable history.
- Reuse existing estimate-series/numbering tables and repository extension; if new normalized columns/tables are needed, add them once in SQLDelight v15→next schema migration. Include exact FK/unique/index/soft-delete and migration checks. Keep old Android Estimates/legacy PDF records visible/readable without auto-upgrade/re-number; no alternative second canonical series registry.
- Post-commit reader must not compute amount or row titles from current active price list. Status updates do not modify revision row counts/total hash.

## 5. Settings-driven suffix and offline distinctness (owner-approved)

**All new numbers must be generated from `EstimateNumberPolicy` stored in Settings and transactional counter; no independent edit field on Save.** Current Settings screen contains template/prefix/width, no suffix; introduce a configurable **suffix policy** in that same screen+SQLDelight settings and in `EstimateNumbering`. Use a versioned/additive approach and preserve canonical full 36-character series UUID in internal `documentNumber`.

For P4C1 choose a minimal safe interpretation without a new issuer profile:
- New public templates include mandatory **`{suffix}`** token (plus `{sequence}`, optionally prefix/year). Persist an optional user-set **human label** for suffix in Settings (e.g., future initials), but its default must not pretend to know the user name/company. Auto-append a **short independently randomized per-document public discriminator** (e.g., 8-10 uppercase safe characters, generated from a separate secure random identity, not a displayed substring of the private series UUID). Treat this combined value as the settings-governed rendered `suffix`. It remains present even with an empty custom human label.
- Rendered public number example only: `AC-2026-00001-K7Q2M8TR`; with future manually set human label, it can become `AC-2026-00002-ІП-H4M7D2QT`. Exact separator/length configurable/extendable, do not hardcode the examples.
- Prevent **local** public number collisions using UNIQUE constraint/retry in same issuance transaction, across duplicate setting labels, backups and imported documents. Avoid changing template or suffix for previously issued numbers; store the **exact printable number** on issue, not regenerate it from future settings or a mutable owner's profile.
- The random public discriminator is **not** full UUID. The full UUID and local UNIQUE guarantee internal identity; short offline printed numbers cannot be mathematically globally guaranteed without coordinated allocation. Do not claim such a guarantee. In a backup-clone scenario two installs may share the same local sequence/human suffix; independent random document discriminator minimizes collisions. If fully portable cryptographic random generation is unavailable on a platform, reuse the existing platform-safe random UUID source to derive a **separate** public random token; never truncate/print the actual series UUID. Surface any collision that remains in imported documents instead of silent merge.
- Future actual first+last name initials and company/address/phone settings are **backlog #114**, not P4C1.
