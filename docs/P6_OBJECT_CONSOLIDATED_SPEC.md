Planning/audit only; це не дозвіл починати production implementation.** P5D #164 / PR #166 має пройти власні gates, merge власником і post-merge FULL. Не змінювати цей PR заради P6. Цей контракт має пріоритет над історичним рішенням 21.11 нижче: зокрема скасовано transient export без номера, незалежний selected UI, згортання груп, обов'язковий архів PDF, відсутність додаткової знижки та незалежність статусів.

## P6A — Об'єкт (рішення 1–8, 26)
1. Єдиний вертикальний список: адреса/підсумки → статус роботи/оплати → клієнт → примітки → Стелі → Зведені кошториси. Зберегти existing moving header, FAB, overlay/градієнти та анімацію адреси.
2. Картка стелі: компактна мініатюра реального збереженого креслення з розміщеними елементами, без сітки/розмірів/літер/інтерактиву; назва, площа, периметр, фінансовий показник; один тап → той самий workspace «Стеля».
3. Фінансовий показник: погоджений individual, інакше остання активна невідхилена версія; іконка статусу справа від суми, без рядка якщо немає відповідної версії. Не live-reprice.
4. Під адресою незакріплена компактна смуга: сумарні площа, периметр, погоджена сума. Округлення лише display; не підміняти недоступні дані нулями.
5. Погоджена сума = finalCents погодженого зведеного (якщо є) + finalCents погоджених individual лише стель, UUID яких НЕ входить до його manifest. Якщо немає approved consolidated — сума approved individual. Не дублювати, не змішувати валюти, checked exact arithmetic.
6. Компактна картка клієнта: ім'я → картка клієнта, контактні іконки лише за доступними даними/діями, примітки клієнта видимі; не додавати fake actions.
7. Примітки об'єкта як є, без згортання та нового механізму редагування.
8. Відкритий список зведених версій newest-first, без згортання; стиль P5D; номер серії один раз; окремий плюс.
26. Статуси робіт і оплати незалежні від кошторисів, чинний механізм без змін.

**Performance gate:** перший вміст об'єкта не чекає мініатюр/фінансів; bounded lazy rendering лише видимих карток + cache keyed by geometry/placement revision, batched financial metadata, без N+1 та без повного live pricing усіх стель. Перевірити відкриття/scroll на фізичному Android з 20–30 стелями, порівняти до/після; якщо відчутна затримка — оптимізувати/спростити, не приховувати її. Технічний спосіб кешу і вимірювання — audit, не нав'язана реалізація.

## P6B — Зведені документи (решта рішень)
9. Одна активна серія на об'єкт, незалежні immutable vN, максимум один APPROVED на об'єкт. Не повертати незалежний selected UI.
10. Новий зведений: initial preselection тільки APPROVED individual; майстер явно переглядає та змінює selection; одна стеля = одна точна version; стелі без доступних збережених документів видимі, але не selectable. Reactive total; selection не пише БД і не змінює статус.
11. Approve consolidated → атомарно APPROVE точні включені individual revisions; попередні approved відповідних стель → SENT. Не торкатися інших стель.
12. Зміна погодженої individual версії, включеної в approved consolidated, після явного попередження/підтвердження → consolidated SENT, нова individual APPROVED, попередня SENT; інші individual залишаються approved. Audit також пряме зняття APPROVED, усі writers та race cases.
13. Явне скасування approval consolidated: підтвердження з checkbox «Також скасувати погодження включених індивідуальних кошторисів», default OFF; за вибором змінювати лише точні включені approved revisions. Атомарно.
14. Додаткова фіксована або відсоткова знижка на SUM(individual finalCents після їхніх знижок); immutable typed discount, reuse P5D exact Long cents/milli rules, checked overflow, same currency. Не змінює individual.
15. Явне збереження обов'язкове перед PDF export/print/share; preview до Save без номера/запису/status. Старий P4C4 transient export path не повинен обходити вимогу. Використати renderer/verified source, а не паралельний фінансовий рушій.
16. Загальний + створює з нуля (правило 10); контекстна дія exact vN створює на її основі з назвою, точним manifest/версіями, знижкою, без silent upgrade. Не зберігати ідентичні версії. Недоступне/логічно видалене джерело у carry — не підміняти мовчки, audit політики для нового Save.
17. Logical deletion exact non-approved vN або всієї серії без approved версій; explicit confirmation, writer recheck, immutable historical content, не перевикористовувати UUID/номери/vN. Не змінювати individual statuses. Історичні посилання на individual tombstones залишаються читабельними для існуючого consolidated/PDF; active selectors не пропонують deleted.
18. Saved consolidated: компактні рядки стель/точної vN/суми; тап → точний historical individual read-only, Back → same consolidated context. Fixed translucent total/actions; status icons і delete protection як P5D.
19. Лише APPROVED consolidated: загальний і per-ceiling drift indicators, компактна кольорова іконка з поясненням при тапі. Нова individual vN сама по собі або додана unrelated стеля не є drift. Reuse P5D check; без повного repricing при open; не змінює суми/status.
20. PDF regenerate із immutable snapshots; архів PDF bytes не робимо. Вміст/суми/креслення історичні, layout може змінитися після оновлення renderer.
21. Лише детальний PDF: кожна стеля, frozen креслення/матеріали/роботи/суми, consolidated number/vN і discount/payable. Reuse P4C4/P5D, зберегти компактне pagination, no current catalog repricing.
22. Налаштовувана numbering: спільний чи незалежні лічильники, окремі префікси, короткі шаблони без suffix (#143), initials як prefix, незмінність старих public numbers, global collision protection across types/mode changes/deletions; shared counter default — пропозиція, уточнити технічно. #143 бажано до P6B.
23. Підтверджений PDF share handoff → consolidated DRAFT→SENT і включені individual DRAFT→SENT, атомарно; APPROVED/REJECTED untouched. Preview/export to file/print/cancel не змінюють status; handoff ≠ delivery proof.
24. Окремий full-screen CMP create/read-only screen; спільна структура, fixed translucent panels, dirty navigation guard, keyboard/insets, обидві теми, Back.
25. Approve new consolidated → старий approved consolidated SENT; exact included individual APPROVED (п.11); checkbox default OFF для зняття approval з виключених стель попереднього manifest; інші untouched; атомарно.
27. REJECTED individual доступні для явного ручного вибору, ніколи auto-select; саме включення не змінює status. Deleted sources не доступні для нового вибору.
