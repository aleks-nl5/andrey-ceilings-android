## 1. Trust and consistency contract

**Repository → verified frozen material → user-selected exact revision IDs → composition → shared pages → exporter.**

- Resolve all selected `seriesUuid/revisionUuid` from **persisted immutable content and receipts**, scoped to **one projectUuid** and one unique measurementUuid each. Do not synthesize `FrozenRevisionVerification` or `contentSignature` from mutable UI state, unsaved DTOs, names, statuses or catalog: only a trusted persisted validator can issue a proof. If existing `ConsolidatedEstimateEngine` cannot consume real v1/2/3 revisions without inventing proofs, build a typed **verified adapter** from `SavedIndividualQuote` in shared KMP and prove parity with existing engine’s negative rules. Adjust P4A DTO only if verifiably needed; never weaken guards.
- Selection resides in the current project composer session. A project change, DB restore/session replacement, explicit cancel/back clears it; no persistent selection table or new series. Normal recomposition/rotation should not silently choose new IDs; validate again before PDF materialization/export to avoid stale source/reference races.
- Statuses DRAFT/SENT/APPROVED/REJECTED and `selectedRevisionUuid` remain **read-only metadata**. All 4 saved statuses allowed if the exact frozen revision is valid; do not silently filter based on client acceptance.
- Same project but different measurement IDs remains separate even if room names match. Same measurement has multiple series and revisions; only **one chosen revision total**. Duplicate rooms/revisions, deleted or foreign/missing rooms, broken receipts, malformed snapshots, wrong currency, invalid totals, overflow and any mismatch fail closed.
- Source of financial truth is the exact immutable `saved.frozen.rows`, `saved.frozen.amounts` and omission set. `total = checkedSum(selected.saved.frozen.amounts.finalCents)` (after room discounts). Do not add new combined discount, recalculate unitPrice×quantity or invent an aggregate number or revision. Each room still prints its pre-discount subtotal, frozen discount and final payable. Distinguish these clearly in project grand total.
- Mixed currencies fail closed. Current mutable project address may be displayed in a distinctly labeled optional nonfinancial field, consistent with P4C3. Room/project title and geometry/annotations are from frozen saved source. Never leak private UUID in print, filenames or error UI.
- Avoid accidental separate paths for PDF preview vs PDF bytes. `EstimateDocumentPages` is the common render output; UI navigation/export may vary by platform, data and totals may not.

## 2. UX acceptance — practical example

Project "Квартира A": Living room series A `v1` and `v3`; Kitchen series B `v2`; Bedroom no saved quote. Initial screen has 0 checkboxes active and no grand sum represented as valid PDF. Master chooses Living → explicitly chooses A/v1 (not newest v3), chooses Kitchen → explicitly B/v2. Bedroom is unselected; missing quote **does not block**. PDF shows Living A/v1 and Kitchen B/v2 as two fully detached frozen sections and one final aggregate payable. Master cancels and nothing is written. Existing individual PDF for A/v3 remains available and unchanged.

- Card rows: `Назва стелі`, explicit checkbox, e.g. `№ ... · v2 · Чернетка/Надіслано/Погоджено/Відхилено · 5 700 грн`. Never show private UUID. Label `Обрано для роботи` is informational; no automatic check.
- Show clear empty, loading, DB error, absent saved documents, unavailable reference, no documents for room, stale selection states. Do not auto-create a quote on confirmation.
- Back/Cancel during loading/export is safe: no accidental partial file or DB mutation; respect existing exporter platform lifecycle. Save/Share/Print on Android only if adapter is available.
- Final aggregate heading can say `Зведений кошторис` with current project title and optional address; **do not invent a new human-visible unique number**. Each room retains own published number/version. Filename neutral safe slug e.g. `zvedenyi-koshtorys-<safe-project-title>.pdf` (avoid overwrite without OS confirmation); avoid UUID and path separators. Date of generation can be visual nonfinancial current metadata, independent from frozen room creation dates.

## 3. Implementation order / checkpoints

1. **Proof first:** write repository-backed RED tests that select mixed v1/v2/v3 with distinct statuses and discounts, and fail on stale/forged/duplicate proof. If legacy DTO cannot be populated honestly, define the minimal secure adapter in shared KMP instead of faking acceptance.
2. **Session/UI:** add project entrypoint and ephemeral composition presenter. Keep display prices on frozen amounts; no global live pricing query in selected source. Ensure composer/selection cancels across object switching and DB restore.
3. **Composite render:** refactor shared document layout into room-section layout + aggregate summary using existing `DocumentMark`/drawing/text pagination and section options. For room breaks ensure no split of room header/first row; long line item titles wrap. Add page numbers or repeat headers following established P4C3 pattern. One empty/optional section never hides mandatory financial tables/totals.
4. **Platform:** Android exporter remains same `EstimateDocumentExporter`; Windows/iOS preview only if export adapter unsupported. AppRoot navigation only if needed, avoid Android-specific price logic.
5. **No DB change** by default. If change claimed necessary: ask explicit scope review in PR and add matched physical SQLCipher migration, rollback, backup tests; do not casually advance schema beyond v20.
6. **Negative and golden tests:** source snapshot before opening→selecting→preview→export/cancel→reopen identical. Compare file text/amounts and live shared pages. Test exceptional cases stale status/selection during preview, old frozen format, partial omissions, Hungarian/long Cyrillic text, multi-room/multi-page, precision `13.7608 → 13.761` and `100 UAH/m² → 1376.10` in already frozen format-3.
7. **CI and review:** run targeted local Android/JVM/Desktop/iOS tests; after pushing wait for same-final-SHA checks to finish before declaring success; attach steps/logs, independent code review, owner APK. Do not close issue or mark Ready/merge.

# P4C4 — зведений PDF за об'єктом з явно обраних frozen-ревізій кімнат

**Батьківський напрям:** #44 (P4, залишити відкритим до прийняття P4C4). **База:** після merged PR #122, main `ecfc028c00d374ae90796b58a0a26d3bb0110e83`, SQLDelight/SQLCipher schema **v20**. P4C3 (#119 / PR #120) з індивідуальним PDF завершено.

## Продуктова мета
На **картці об'єкта** майстер обирає потрібні приміщення (checkbox); **для кожного обраного — рівно одну явно визначену вже збережену immutable індивідуальну ревізію** (включно з v1/v2/v3, незалежно від статусу, newest чи selected pointer). Після перевірки отримує **спільний CMP A4 preview, опціональне оформлення і PDF** з повними окремими секціями приміщень та спільним фінальним підсумком. Це **разовий документ**, не новий saved estimate.

## UX-поведінка (проєктне узгодження 19.11.2026; дрібні деталі можна уточнити за APK)
1. У **Project Details** окрема зрозуміла дія **«Зведений кошторис»** поряд із наявним переглядом індивідуальних, без перебудови top bar/FAB/анімацій. Відкрити повноекранний CMP діалог/route з Back/Cancel.
2. Перелік **активних кімнат/замірів цього об'єкта**, без автоматичних фінансових позначок. Для кожної: checkbox, назва, інформація про наявність або відсутність saved revision. Кімнати без кошторисів видно, але **не можна ввімкнути для друку без вибору валідної frozen-ревізії**; є шлях відкрити відповідний замір для її створення. **Невибрані** кімнати нічого не блокують.
3. При включенні кімнати користувач **явно обирає** конкретну пару `seriesUuid + revisionUuid`: у меню показувати публічний номер, vN, назву, статус, frozen остаточну суму, позначку «обрано для роботи» лише як інформацію. Не вибирати автоматично latest, active, approved чи selected. Пропозиції одного приміщення не зливати самочинно; не дозволяти дві ревізії однієї кімнати в одному зведенні.
4. Порядок секцій — стабільний порядок кімнат об'єкта (без нового reorder UX у цьому PR). Зміна чекбокса/версії міняє лише **transient in-memory selection**. Показати список кімнат, frozen суми і сукупне `Разом`; ніколи не відображати перераховану за прайсом суму. Порожня вибірка, одна обрана без ревізії, дублікати чи invalid/stale data вимикають PDF з чіткою причиною. Однієї обраної кімнати достатньо.
5. Після `Переглянути зведений PDF` створити детерміновані **секції з власним frozen кресленням, рядками, знижкою, partial omissions, підсумком, публічним номером + vN**, за шаблоном P4C3. Об'єктний заголовок і заключна сторінка/секція із сумою **остаточних сум до оплати** всіх включених ревізій після їхніх індивідуальних знижок. **Не застосовувати нову знижку до суми**. У точному коді зіставити legacy назву `subtotalCents` у `ConsolidatedEstimateEngine` з `QuoteAmounts.finalCents`: тестом довести відсутність подвійної знижки/використання pre-discount subtotal.
6. PDF A4: коректний перехід між приміщеннями/сторінками, повтор заголовків/нумерація сторінок, кирилиця, багатосторінкові таблиці, фото/контакти лише якщо коли-небудь підключені наявні необов'язкові provider-и; ніяких вигаданих реквізитів. Формат файлу без приватних UUID або фіктивного номера нового зведеного кошторису. На Android Save/Share/Print через існуючий exporter. На Windows/iOS: лише реальні підтримувані можливості (#42), без фіктивного успіху експорту.
7. **Cancel/Back/помилка експорту/повторне формування:** ніяких INSERT/UPDATE в estimate, measurement, price, workflow, selected-pointer, numbering; не створювати consolidated series, ревізії, номера, receipt. UI не змінює вміст навіть якщо змінено статус чи selected pointer після початку preview; при наступному відкритті читає чинну immutable ревізію за точним UUID.

## Технічна інтеграція (не винаходити другий рушій)
