## 1. Конкретний користувацький сценарій

Майстер відкриває збережений замір «Кухня» (4 × 3 м) через Android «Заміри» або «Об'єкти» (або Windows Objects). На спільному CMP-кресленні:

1. **Без прайсу**: «Додати перешкоду» → позначає **прямокутний короб/вентканал**, задає ширину/довжину/положення та примітку; окремо «Позначити отвір» → **коло**, діаметр у мм, прив'язка до стін. Обидва об'єкти — *анотації* з власними UUID, семантикою, world-mm геометрією, незалежні від `MeasurementElement`. Видно у деталях і на Canvas. «Отвір» **не** є вирахуваним із площі стелі отвором: це лише геометрична позначка.
2. **Із прайсу**: існуючий element, створений з catalog selection зі snapshot `placementKind=AREA`, `quantityMode=MANUAL`, `unit=м²` (або `шт.`), можна явно «Розмістити». Проста фігура **площа в м²** або **один об'єкт у шт.**, залежно від одиниці; display показує **окремо** заявлене та геометрично розміщене. Без `code`/title heuristics та без auto-binding до каталогу. Можна створити два area overlays тієї ж позиції.
3. **Форми:** прямокутник — компактний preset із двома протилежними кутами, який створює повноцінний polygon із 4 вершинами (не окремий несумісний тип таблиці). Інші багатокутні форми — **простий замкнений polygon від 3 до 16 вершин** (без самоперетинів). Коло — центр + **введений виміряний радіус/діаметр**; не плутати діаметр із радіусом і не зберігати коло як приблизні піксельні сегменти.
4. Тап по відповідній фігурі виділяє її UUID і відповідний item у панелі; є редагування положення, вершин (для polygon), радіуса/діаметра (для circle), примітки/семантики та видалення з підтвердженням. Approx через canvas tap/drag; точні виміряні прив'язки від обраних стін можна задати чисельно, using existing P3C3 `WallAnchor`. Undo/Redo і normal/fullscreen працюють із **тим самим** draft/model. Save/reopen, process recreation, backup/restore зберігають identity/геометрію.
5. Зміна основного контуру стелі виконує консервативний перерахунок прив'язок; якщо фігура/частина її виходить за контур, втрачено стіну або опору, лишає останні відомі дані та `unresolved` і показує «Перевірити/Пізніше». Нічого не видаляється, не переноситься на найближчу стіну, не віднімається з площі.

## 2. Типізований KMP-домен: shape / role / association — окремі осі

Один `AreaFeature`/ `AreaPlacement` (ім'я обґрунтувати відповідно до репо) має:
- `uuid` stable, **пряму** `measurementUuid` приналежність, `elementUuid: String?` **лише** для явно прив'язаного catalog AREA selection; unpriced annotation не має фіктивного element. Обмежити FK/ownership та soft-delete обох батьків.
- `role` як розширюваний typed enum: `GENERAL_AREA` / `OBSTACLE` / `VOID_MARKER`, а не boolean `subtractArea`; optional note/name. `role` НЕ визначає прайс/одиницю і **не є** фізичним boolean-оператором.
- Sealed `AreaShape.Polygon(vertices: List<PointPositionMm>)` (3..16) і `AreaShape.Circle(center: PointPositionMm, radiusMm: Long)`, координати/радіус **Long mm**. Прямокутник — preset polygon, а не окреме непрозоре поле. Всі об'єкти мають типізований stable shape; orientation для polygon визначається vertices, без дублювання persisted angle, розмірів та незалежних координат.
- `createdAt/updatedAt/deletedAt`, `contourUpdatedAt`, `lastCeilingEditUuid`, `needsReview`, `unresolved`, точність/джерело даних, **anchor для кожної визначальної позиції** (vertices polygon, center circle), `anchorGeometryJson`/last-valid context, `confirmedAt/deferredAt` per feature/measurement context, версії CAS.
- **Exact** дозволено лише після valid measured physical anchors для **всіх** vertices polygon або center circle **і явно виміряного числового радіуса/діаметра**; free tap/drag ніколи не стає measured exact. Не вигадувати опори для раніше приблизних або застарілих даних. Перевикористати геометричні обмеження P3C3, `ceiling_walls.uuid`, two-wall perpendicular offsets + along/inward fallback, visible foot/interior/near-parallel checks; без дублювання solver.
- `unresolved` **sticky**: втрата wall identity, неможливий remap, порушення всього footprint або self-intersection не може бути скинута простим drag/resize/resize контуру; відновлення тільки після нового валідного обміру визначальних точок + explicit confirm. `Пізніше` durable, failed/uncertain Save не скидає попередній статус.

## 3. Геометрія/валідація та пояснення меж

- Фігуру вважати **valid placement** лише якщо вона ненульова, проста, з bounded integer-mm координатами, весь **footprint всередині** основного validated polygon; не досить перевіряти лише vertices/center. Довести всі polygon edges проти boundary, у тому числі U/L увігнутий контур та segment touching; для circle перевіряти весь круг (`center inside` + строго достатня відстань від центру до **кожного** wall segment за радіусом), а не лише 8 sampling points. Boundary-attached конструкції, які торкаються стіни, залишати `unresolved`/пояснювати, поки немає окремого доведеного правила. **Ніякого прихованого snap або clipping.**
- Нормальні перекриття AREA/OBSTACLE/VOID з іншими фігурами можуть існувати як позначки (не блокувати без потреби), але не робити «union», не віднімати overlapping ділянки, не змінювати headline ceiling `areaSquareMeters`/ `perimeterMeters`. Явно пояснювати, що сума геометричних площ **не** є чистою площею стелі і не є перевіреним об'ємом вирізів.
- Детермінована площа: для polygon використати integer shoelace (можлива половина мм²) з bounded overflow-safe sums, наприклад `twiceAreaMm2` як canonical; circle не апроксимувати піксельними багатокутниками, обчислити канонічне integer-rounded mm² за **одним KMP+SQL exact fixed-point pi policy** (напр., `pi≈3_141_593/1_000_000` з overflow checks). Точне число/межі зафіксувати однаково для KMP, SQL і tests. **Не round кожну фігуру перед сумою:** сумувати точні canonical areas, а `м²` у milli (= 0.001 м²) округляти **раз після сумування**, half-up, без Double або DPI-dependent persistence; `шт.` = 1000 milli за кожен valid object. Показувати mm² / 0.001 м² precision і за потреби маленьке valid shape <0.0005 м² без підміни на «не розміщено».
- Для `CatalogSelection(placementKind=AREA)` permit лише **`QuantityMode.MANUAL` + unit `м²` або `шт.`**, `Unknown/Exact/Range` у рамках чинної quantity-моделі; `CeilingArea` не є площинним об'єктом, `CeilingPerimeter`/ `EnteredLength` теж не імплікують локальну область. `Wish`/ `NONE`/ `POINT`/ `LINE` не стають AREA автоматично. Видалення/перейменування прайсової позиції не змінює збереженого snapshot. При `Unknown` не робити вигаданий cap, при `Range` не використовувати середину як Exact.
- `placedQuantityMilli`/placementStatus відображають **лише валідні resolved** overlays linked element, окремо від заявленої `ElementQuantity`; unresolved резервують останню виміряну canonical площу/кількість при Exact/Range-capacity, але не входять до valid placed total. Кількість змінюється **лише явно** («Взяти з креслення», з preview/CAS), не після drag чи Save. Для unpriced annotations **ніяких** price entries/placedQuantityMilli/estimate lines. Дозволити явний link annotation→catalog тільки якщо це окремо валідований user intent; інакше лише create AREA catalog overlay, без stealth relinking.

## 4. Реальний мінімальний CMP-каркас без великого UX-редизайну

- **Один** існуючий shared `MeasurementDrawing`, одна normal/fullscreen editor model із mode/gesture arbiter; overlays point/line/area одночасно, precedence селекції при накладанні обґрунтувати. Не порушити pan/pinch/fit/point-marker/line-select/move/cancel. Відстань hit-test для circle edge/filled interior і polygon boundary/interior з доступним target, стабільний вибір UUID, including short/boundary variants; необмежений gesture list/застаріле selection state не допускаються.
- Доступні окремі прості дії «Позначити перешкоду» / «Позначити отвір» (без прайсу), «Розмістити» (тільки сумісний catalog AREA), polygon/rect/circle на кресленні. Чітко відрізняти приблизний draft від збереженого і `unresolved` від valid. Після Save/reactive reopen ті самі UUID у details і fullscreen, із видимими area/dimensions/notes/status.
- Rect preset: два протилежні кути створюють 4 vertices; polygon: по точках 3..16 з явним завершенням; circle: центр на Canvas і поле діаметра/радіуса з введенням `2,5`/`2.5` (у метрах) та валідованим mm. Ввід для існуючого polygon vertex — tap/drag approximate або measured wall anchor form; circle center anchor і numeric diameter. Повний дизайнерський сценарій не закріплювати тут, він #95.
- CRUD, selection ↔ logical item, properties, Undo/Redo, dirty Back, route, orientation, process recreation, window insets, zoom, Android Compose touch / Windows mouse. У fullscreen та normal — той самий draft, без незалежних SQL operations. Не позначати placement exact від піксельної зміни.

## 5. Найкритичніше: атомарний контур + POINT + LINE + AREA, вбудована БД

- **Нова additive SQLDelight v12→v13 migration** (звірити фактичну версію); нова нормалізована `area_features`/ `area_placements` із FK на `room_measurements.uuid`, optional FK на `measurement_elements.uuid`, typed role+shape, validated bounded JSON coordinates або окремі child vertices, geometry/provenance, active indexes/soft delete, canonical area payload, CAS timestamps, idempotent operation receipts. Прямий measurementUuid обов'язковий для unpriced objects.
- Розширити існуючі `ceiling_operations`/ `ceiling_operation_results` **до complete set area**, без часткового Save. Один SQL writer lock **до читання**, перевірка parent ownership/active/deleted state, complete set POINT+LINE+AREA, actual `expectedUpdatedAt` для кожного, shape/unit/quantity constraints, invalid geometry, durable valid/review/unresolved, CAS і full result receipt. Одна транзакція contour + points + lines + areas + explicit quantity correction. Ні line-only, ні point-only, ні area-only SQL writer не може обійти guards при зміні контуру, версій, snapshot summary або батьків.
- SQL має незалежно валідувати shape, canonical area, allowed role, valid boundary, anchor source/provenance, summary/optional element link, last-valid context і immutable receipts; **KMP-side validation недостатньо, якщо raw SQLite може записати неправильну площу, вкрасти чужий UUID, сфальсифікувати `EXACT` або пропустити complete set**. Якщо SQL enforcement для певного shape не може бути доведено, звузити реалізацію цього shape з чесним позначенням, **не** вимикати перевірки чи створювати неконтрольований UPDATE. Тести direct-SQL bypass із `foreign_keys=OFF`.
- Повтор `operationUuid` + identical payload — reconcile без повторного запису; інший payload — fail closed. Uncertain commit/rollback не перетворювати на «не збережено» без **фізичного outer rollback proof**. Restore session/rotation не запускає друге Save. Cleanup при видаленні area/element/measurement/project, soft delete orphan guards, reactive Flow.
- v12 fresh schema == migrated v12→v13 **повний fingerprint**, physical populated deployed-v12 fixture (point/line/anchors/operations/tombstones/declared qty), migration rollback/reopen/reader/writer proofs, збереження **обох** deployed v10 lineages, v11 і v12. **НЕ переписувати** `9.sqm`, `10.sqm`, `11.sqm` та frozen historical fixtures; не вдавати нові гарантії на старій версії. Не змінювати шифрування, ключі, WAL і portable backup format, але оновити backup preflight/integrity, Android production Keystore+release migration, Windows encrypted SQLCipher та iOS Simulator SQLCipher validation. Unsupported partial/hybrid schema — fail closed, no reseed/reset/data loss.
