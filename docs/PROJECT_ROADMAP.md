# План розвитку Andrey Ceilings

Цей файл — робочий чекліст проєкту. Перед завершенням кожного етапу перевіряємо критерії приймання, CI та APK на реальному Android-пристрої. Позначаємо пункт `[x]` лише після фактичної перевірки.

## Принципи роботи

- [ ] Кожен етап або незалежну групу змін оформлювати окремим Pull Request (PR).
- [ ] Не зливати PR без перевірки diff, успішної CI-збірки та потрібних тестів.
- [ ] Після значних змін збирати APK і перевіряти його на телефоні.
- [ ] Не поєднувати великий редизайн, зміни архітектури та нову бізнес-логіку в одному PR.
- [ ] До завершення міграції поточний Android UI на `main` є еталоном; цільовий напрямок — поступовий перехід на Compose Multiplatform + Kotlin Multiplatform для Android, iOS і Windows. План: `docs/architecture/CMP_KMP_MIGRATION.md`.
- [ ] Ціль — перенести розрахунки з Go в Kotlin Multiplatform; Go/AAR видаляти лише після parity/regression tests.
- [ ] Зберігати offline-first та готувати модель даних до можливої майбутньої синхронізації, але не реалізовувати її на цьому етапі.
- [ ] Цільова БД має бути зашифрована на Android, iOS і Windows. Фото, креслення та PDF окремо шифрувати не потрібно.
- [ ] Планова заміна Room → SQLDelight; поточні записи — лише тестові й можуть бути скинуті під час міграції. Шифрування SQLDelight перевірити окремо на кожній платформі.
- [ ] Не вважати функцію готовою лише тому, що проєкт компілюється: перевіряти її поведінку на пристрої.
