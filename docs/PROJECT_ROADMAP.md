# План розвитку Andrey Ceilings

Цей файл — робочий чекліст проєкту. Перед завершенням кожного етапу перевіряємо критерії приймання, CI та APK на реальному Android-пристрої. Позначаємо пункт `[x]` лише після фактичної перевірки.

## Принципи роботи

- [ ] Кожен етап або незалежну групу змін оформлювати окремим Pull Request (PR).
- [ ] Не зливати PR без перевірки diff, успішної CI-збірки та потрібних тестів.
- [ ] Після значних змін збирати APK і перевіряти його на телефоні.
- [ ] Не поєднувати великий редизайн, зміни архітектури та нову бізнес-логіку в одному PR.
- [ ] UI і навігація залишаються нативними Android (Kotlin/Jetpack Compose); розрахункова логіка має бути в Go.
- [ ] База даних повинна бути зашифрована. Фото, креслення та PDF окремо шифрувати не потрібно.
- [ ] Не вважати функцію готовою лише тому, що проєкт компілюється: перевіряти її поведінку на пристрої.
