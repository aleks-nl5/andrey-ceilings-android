# Підписати APK для поточного PR — без iOS-раннера

**Мета:** власник може отримати підписаний Android APK із **актуальної гілки відкритого PR**, навіть якщо iOS чекає Mac-раннера. Ніяких номерів GitHub Actions, SHA або перемикання робочої гілки не потрібно.

## Найпростіший спосіб — прямо у PR

1. Відкрий потрібний PR (наприклад, [PR #157](https://github.com/aleks-nl5/andrey-ceilings-android/pull/157)).
2. У полі **Leave a comment** напиши лише `/sign-apk` та натисни **Comment**. Команду приймаємо **лише від власника репозиторію**.
3. У вкладці [Actions](https://github.com/aleks-nl5/andrey-ceilings-android/actions) відкрий **Sign PR Android release APK**. Після успіху в його артефактах з'явиться `pr-fast-android-release-apk` → `app-release.apk`.

Workflow сам дізнається номер PR із коментаря, перевірить **його поточну гілку й commit SHA**, знайде **найновіший FAST run для саме цього коміту** та підпише лише створений там unsigned APK.

## Альтернатива — GitHub Actions, лише номер PR

1. [Actions](https://github.com/aleks-nl5/andrey-ceilings-android/actions) → **Sign PR Android release APK** → **Run workflow**.
2. Залиш **Branch: main**, оскільки **тільки захищений код підписувача** виконується з `main`. APK обирається **із гілки PR, не з `main`**.
3. Введи в `pr_number` тільки номер PR, наприклад `157` → **Run workflow**.
4. Завантаж `pr-fast-android-release-apk` із артефактів завершеного запуску.

**Увага:** ручні команди активуються тільки після об'єднання PR із цим workflow у `main`. Це НЕ означає об'єднання PR застосунку.

## Захист підписування та перевірки

- Підписувач працює виключно з довіреної `main` і **ніколи не виконує код PR**; ключі не надходять у PR-раннер і не друкуються в лог.
- `/sign-apk` реагує лише на точний коментар **власника репозиторію** до PR. Звичайний `workflow_dispatch` обирає лише поточний відкритий PR цього репозиторію до `main`.
- Власник не вказує FAST run: береться **найновіший** запуск `PR fast checks (no FULL)` для `head SHA` поточної гілки. Якщо останній запуск невдалий по Android/Windows, не можна обійти його старішим успішним.
- Перед підписуванням перевіряємо GitHub workflow identity, поточний PR head і той самий `run_attempt`: Classify, Android release/JVM, Windows compile/scene — **успішні**.
- iOS може чекати, виконуватися, бути успішним або скасованим **лише без виділення раннера та з нулем виконаних кроків**. Справжня помилка чи скасування після початку iOS забороняють підписування.
- Підписуємо тільки однозначний, не протермінований `pr-internal-unsigned-release-apk` з підтвердженого FAST; перевіряємо ZIP, zipalign, package name, відсутність існуючого підпису та фінальний `apksigner verify`.
- Ручне підписування — **лише для власницького APK smoke-тестування**: воно не робить CI зеленим і не дає дозволу на Ready чи merge.

**Якщо PR змінено новим комітом:** спочатку дочекайся нової Android + Windows збірки, потім повтори `/sign-apk`.
