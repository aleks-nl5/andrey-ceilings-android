## Implementation guardrails / derived engineering defaults (not new product decisions)
- Model actual series segments and exceptions with unique immutable keys; one occurrence per original date per series rule (if custom rule permits multiple same-day slots, define deterministic original slot discriminator). Retain root identity across split, preserve keys of already addressable surviving occurrences via explicit mapping/alias rather than recomputing from moved date; collision-free for new occurrences. Define mapping algorithm and test before use; ambiguous exceptions detach only when active and meaningful; preserve terminal/tombstone semantics. Splits must handle occurrence-count remaining, inclusive end date, individually moved exceptions across boundary, stable links and completed history; prior/past occurrence meaning uses scheduled original key and actual effective date where appropriate. Do not silently rewrite history.
- Work schedule supports exact intervals, all-day and date-only. Multi-day schedule may have relative day offsets for recurrence, each editable; validate nonempty date set, ordering, positive intervals after DST resolution; local day boundaries in event timezone (23/25-hour DST days). Timed work compared as instants; define display grouping in working zone vs event-local date explicitly and show differing TZ to avoid ambiguity. Date-only remains date, no invented time. Use injectable clock/common kotlinx-datetime; no java.time in common.
- Query bounded overlap by indexed candidate ranges and active rules, include exceptions moved into/out of window even if original key outside; no N+1, no scan of entire generated history, cap cache/prefetch. For upcoming use deterministic ordering and progressive bounded windows to find sparse future events; do not report no work solely because one short query window empty. Search explicitly indicate dynamic horizon vs persisted records; do not hide moved exceptions. Proposed 90-day conflict window starts at max(today, effective start/edit boundary), clip to finite end/count; check exact individual dates regardless, clearly indicate unverified beyond horizon. Compare candidate series against itself where distinct intervals overlap, exclude only the specific occurrence being edited. Confirmation bound to draft + canonical conflict fingerprint; acquire writer and recheck entity status, version, references, conflicts before commit. No stale confirmation or check-then-write race.
- History of terminal occurrences and previously persisted exceptions remains immutable under forward edits. For bulk cancel/delete/project delete use bounded interval/rule termination or state ranges for virtual occurrences, not millions of rows; preserve terminal exceptions and effective historical labels. For linked deletion verify confirmation against current impact, rollback entire action if failure. Keep explicit ceiling scope vs whole-project distinction even if last selected ceiling deleted. Keep direct client link distinct from effective project client; resolve precedence clearly. No geometry, quote/payment status mutations; completion of montage offers explicit object workflow change only. No hidden event creation from createdAt.
- New tables with CHECK/UNIQUE/FK as appropriate, indices and tombstones; no plaintext or destructive fallback. Stable standard type codes and deterministic seeding idempotent on fresh/migrate/restore; localized display from shared resources, archive custom types without breaking history. Restore business prefs but not device-local mode/integration. Use existing encryption and rollback mechanisms; no new permissions/alarms/provider mappings in P7A. No CI trigger/policy edits; if test routing needs additions for new test classes, minimal explicit registration per existing policy.
- Maintain coherent transactional projections for calendar/dashboard/object/search, cancellation of stale flows, bounded memory, loading vs error vs empty, previous cached values on transient refresh only within same session. Avoid DB on UI thread, no SQL rerun every minute. Benchmark representative large dataset / recurring sparse series and record actual results, not claimed measurements.
- Shared CMP: week/month/list, compact colored dots and one schedule list, Today and period swipe, selected-day behavior per spec, localization/theme/insets/IME/Back, one explicit-save form with dirty exit guard, compact move and conflict dialogs, contextual swipe/menu delete, block 4 dashboard/2 object, global search with exact route, settings via existing general settings. Preserve central + measurement and all P6 features. Follow 46 product decisions, not superseded older issue text. Avoid adding gear in calendar or redesigning P8.
